Source: shoroku run-owned-seats S-89

A fix wave over a passage plan supersedes passages in every file it touches.
In the run-owned-seats fix wave that was thirty-three passages in nineteen of
twenty-three tasks, against the one passage the prompt named. The amendment
itself was mechanical — anchor on the block's unchanged first and last lines,
replace by split/join, with `verify` as the check — and one block in
thirty-two had no anchor.

To decide: whether `verify` gates a fix wave's boundary, and who amends the
superseded passages; the fix-wave prompt then says both.

Kin: issue-7f2a (superseded P-blocks that `verify` reads red forever) and
issue-96f2 (a fix wave has no instrument aimed at it).

Carrier topic: `passage-check-hardening` — whether `verify` gates a fix
wave's boundary and how superseded passages are amended is the instrument's
contract.
