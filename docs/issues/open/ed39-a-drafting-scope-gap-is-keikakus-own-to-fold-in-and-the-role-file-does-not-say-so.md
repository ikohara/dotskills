Source: shoroku shoroku-at-close

Measured on `shoroku-at-close`. Two real scope gaps found while drafting the
plan — `templates/shoroku-brief.md`'s stray interim wording, and
`templates/kanri.md`'s ledger-template mismatch — were raised to Kanri as
needing a ruling. Kanri's actual ruling was that both were plan-scope drafting
judgment, squarely the drafting Keikaku's own to make and not a Kanri decision
in general, and both were folded directly into the plan rather than opening a
new task or batch.

A round-trip to Kanri was paid twice for a ruling the role file could state
once. The default belongs in `roles/keikaku.md`: fold the gap in on the drafting
Keikaku's own call, and escalate only when the fold-in itself is ambiguous —
which batch it belongs to, or whether the spec's own scope excludes it on
purpose.

The Keikaku-guidance issues already on file (issue-b58d, issue-e6b0,
issue-bf75) carry nothing on this.

A process gap, not a user-stated need, so no paired requirement.
